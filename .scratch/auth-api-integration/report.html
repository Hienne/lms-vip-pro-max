Summary

Change map

Three layers move together. Contracts describe what the backend sends: the envelope helper unwraps data so callers never see the wrapper. Session code in apps/lms/src/app/core turns a login into a stored token and a Profile. Mocks lose the old auth fixtures, and the v1 endpoints have none on purpose: the mock API interceptor lets an endpoint without a fixture go to the network, which is how auth reaches the real backend in dev while every other screen stays mocked.

Ticket 01: contract

1.1 Envelope unwrapping

libs/contracts/src/lib/http/envelope.ts:9. EndpointClient parses every response with the endpoint schema, so the wrapper is handled in the schema itself and callers receive data directly.

envelope(DataSchema)
  parse { responseId, timestamp (iso, offset or local), status SUCCESS|ERROR,
          messageCode, message, messageTitle, data: DataSchema }
  transform → body.data           (a body without the wrapper, or a bad data, fails the parse)
Needs review: errors and messageCode are parsed but never read; the backend error contract is deferred (DEC-005). The timestamp format (offset or local) is a guess from the sample; a different shape from the real server makes every call fail the parse (see Merge Danger).

2.2 Interceptor order

app.config.ts:40-44: sessionExpiry → bearer → dev features → mock API → apiBaseUrl. The bearer interceptor must run before apiBaseUrlInterceptor, which makes the path absolute; the test for startsWith('/api/') therefore can never match another origin (bearer.interceptor.ts:12-17). Needs review: the order is a hidden dependency. Moving bearerInterceptor after apiBaseUrlInterceptor would silently stop sending the token. The spec composes the real pair, so that regression fails a test.

Ticket 03: logout

SessionStore.signOut()                                          session.store.ts:151

Why: a 401 on logout means the token is already dead, which is the outcome the user wanted. Without the exemption it would start the "session expired" flow on top of the logout (DEC-020).

Needs review: logout revokes every token of the account, so signing out in one tab or device ends the others. That is the backend's contract, stated in the endpoint comment.

Ticket 04: retire the mock auth

Needs review: in dev, the old paths /api/auth/login|logout|profile now match no fixture, so the mock interceptor lets them reach the network. Nothing calls them any more, but a forgotten caller would hit the backend instead of failing loudly.

Merge Danger

Door: two-way for code, one-way for sessions. Reverting the branch restores the mock sign-in. A user already signed in with the new build holds a lms.accessToken entry the old build ignores, and the old build's mock session is not restored, so they sign in again. The backend side effect (logout revokes every token of the account) cannot be undone from this repo.

Safety fact

The bearer token is attached only to same-app /api/ requests and never to login, assets or another origin. Level: ran.

$ cd apps/lms && npx vitest run bearer.interceptor
 ✓ bearer.interceptor.spec.ts (5 tests)

The spec composes the real bearerInterceptor and apiBaseUrlInterceptor and asserts: header present on /api/courses with a token, absent without a token, absent on login while a token is stored, absent on /assets/i18n/vi.json and on https://other.example.test/api/x. If the interceptor order or the prefix test regresses, one of these fails. Limit: the safety fact covers the interceptor, not storage exposure (see risk 3).
