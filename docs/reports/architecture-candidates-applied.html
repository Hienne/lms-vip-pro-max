1 · Who serves an endpoint 13f6990

What changed
defineEndpoint takes served: 'backend' | 'mock' (default backend). The six adminOrgEndpoints and shellEndpoints.navCounts are served: 'mock'. EndpointClient.isServed(endpoint) answers for the build; UserDetailStore and ShellStore use it instead of APP_CONFIG.mockApi. The interceptor routes by served. A menu group can declare requires endpoints; ROLE_MANAGEMENT requires the three role endpoints, and knownFunctions / toProfile leave the function out while any is not served.
Decision to confirm
Hiding is the "simplest choice": in staging (mockApi: false) the Roles entry disappears from the sidebar, the profile's function list, and the route guard (the page answers 403). The same applies to any future group with requires.
Files
libs/contracts/.../http/endpoint.ts, admin-org.endpoints.ts, shell.endpoints.ts, core/http/endpoint-client.ts, core/routing/screens.ts, core/menu/menu-catalog.ts, core/session/{to-profile,session.store}.ts, user-detail.store.ts, shell.store.ts, mock-api.interceptor.ts.
Tests
isServed for both kinds under both flag values; knownFunctions hides a function with an unserved endpoint; toProfile drops it from nav and menus; the fixture spec lists exactly the served: 'mock' endpoints. Specs that use EndpointClient now provide a test APP_CONFIG.

4 · One failure classifier d74b70d

What changed
toAppError takes the kind from MESSAGE_CODE_KIND, then the HTTP status (401 unauthorized, 403 forbidden, 0 offline), then the fallback. The expiry interceptor calls toAppError(e).kind === 'unauthorized' and keeps its me/login/logout exemptions; isUnauthenticated is deleted. The passwordChangeRequired kind, its message and PASSWORD_CHANGE_REQUIRED_CODE are deleted (nothing branched on them).
Behaviour change
A 401 with any code is unauthorized (a wrong password is now unauthorized, not server; login is exempt from expiry, and its message still comes from the backend). A 403 with any code is forbidden.
Tests
Status/code table in app-error.spec.ts; a 401 with an unlisted code ends the session in session-expiry.interceptor.spec.ts; envelope and session-store specs updated.
