# Visual design: designed, not generated

How UI in this repo looks. The mockup in `lms-mockup/` was generated by an AI tool, and porting it
1:1 carried its generic template look into the app: eyebrows over every title, icons in tinted tiles,
gradient heroes, coloured edge stripes, badges everywhere, pastel placeholder art, semibold on
everything. The review with evidence and the fix plan is `docs/reports/design-system-review.md`.

Read this before building or restyling any UI (library piece, domain UI, layout or page), before
converting a mockup screen, and before writing UI copy. `ui-library.md` says how UI is built; this
doc says how it looks.

## Precedence

- The mockup decides **what** a screen offers: its data, actions, states, behaviour and the meaning
  of its copy.
- This doc decides **how it looks**: hierarchy, decoration, colour use, type, shape, density and
  motion. Where the mockup, a neighbouring file or the `/design-system` page uses a banned pattern,
  do not reproduce it in the code you write: build the replacement below and list the change as a
  deliberate difference in the pull request.
- Existing code is not a precedent. The patterns under
  [Known violations](#known-violations-do-not-copy) are scheduled for removal: never copy or extend
  them.

## Principles

1. **Real content first.** The first screenful shows the user's work (the next lesson, what is due,
   the table they came for), not a greeting, banner or illustration.
2. **Hierarchy from type, not decoration.** Size, weight and colour order the page. Tiles, stripes,
   badges and uppercase labels are not hierarchy.
3. **Colour means one thing.** Teal is action and selection, hoa mai yellow is achievement, status
   colours are state. Nothing is coloured for variety.
4. **A work tool for bank staff.** Calm, dense and aligned: many rows per screen, numbers in columns.
5. **Vietnamese first.** Sentence case, no small uppercase labels, diacritics never clip.
6. **Every element earns its place.** If removing it loses no information and no action, remove it.

## Banned patterns and their replacements

| Never                                                                                                                       | Build instead                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| An eyebrow: a small uppercase label above a title (`ui.eyebrow`, `eyebrow=` on `ui-page-header`, section numbers like "01") | Nothing. The sidebar and the breadcrumb give context.                                                                               |
| `text-transform: uppercase` or letter-spaced small labels (nav groups, table headers, menu labels, card meta)               | Sentence case with `@include ui.text(sm, muted)` and `ui.weight(medium)`. Uppercase only for acronyms and codes (CIF, EOD, NV-101). |
| An icon inside a tinted square or circle (KPI tile, list tile, dialog icon, empty-state circle, feature card)               | No icon, or a `ui-icon` of size `sm` or `md` inline with the text it labels, with no background.                                    |
| A feature or benefit grid (icon, title, blurb, repeated 3 or 6 times), including on the sign-in page                        | Nothing, or a plain list.                                                                                                           |
| A status tone (`success`, `warning`, `danger`, `info`) on a category: role, "Bắt buộc", course type, unit                   | Text, or a neutral `uiBadge`. Status tones go only on state: result, due date, error, locked, published.                            |
| A badge for an attribute (staff code, account type, role, unit), or several coloured badges on one row or card              | Text in a meta line or a `dl`. At most one coloured badge per row or card.                                                          |
| Chips or pills that only list values (permissions, tags)                                                                    | A comma-separated or two-column list. Chips are for toggles and filters only.                                                       |
| A coloured edge: `border-left` or `border-top` wider than 1px on a toast, tip, card, nav item or result                     | A 1px `border`; the icon or the label carries the status. The active nav item is `nav-active-bg` with `nav-active-text`.            |
| A gradient, watermark, blurred or decorative shape, or glass (`backdrop-filter`)                                            | A flat fill: `surface`, `surface-2`, or `primary-strong` for a brand panel.                                                         |
| A hero banner or a greeting at the top of a page ("Chào …, hôm nay học gì tiếp nhỉ?", "Chào mừng trở lại")                  | `ui-page-header`, then the first real content, such as a "Tiếp tục học" card with the lesson, the course, the % and one button.     |
| Placeholder art: a pastel block with a centred icon, an enlarged Lucide icon, decorative circles                            | A real image with a fixed aspect ratio, or no art.                                                                                  |
| A centred empty state with an icon circle inside a card or a table                                                          | Inline: one `text-muted` line and an action link, left-aligned. A whole-page empty state: title, text and button, left-aligned.     |
| Entrance motion on page content (fade or slide on load, `ui.animate(enter)` outside overlays), hover lifts                  | No motion. See [Motion](#motion).                                                                                                   |
| A slogan or tagline (above all two clauses joined by an em dash), self-praise chips ("WCAG 2.2 AA", "Dark mode")            | Plain, specific words: what the screen is and what to do on it.                                                                     |
| A demo or mockup note in the product ("Bản mockup v2 · dữ liệu giả lập")                                                    | Shown only when `environment.mockBackend` or the dev tools are on.                                                                  |
| Two feedback messages for one event (two toasts, or a toast and an alert)                                                   | One.                                                                                                                                |
| Purple, violet, or a colour copied from a default palette (Tailwind's `#7c3aed`, `#ede9fe`)                                 | Tokens derived from the brand.                                                                                                      |

## Type

- `ui.font(sans)` everywhere. `ui.font(display)` only on h1 and h2, at `ui.text-size(xl)` (22px) or
  larger.
- Weight follows the role, and a screen uses at most three weights:

  | Weight | Key                 | Use                                               |
  | ------ | ------------------- | ------------------------------------------------- |
  | 400    | `regular`           | body text, inputs, table cells                    |
  | 500    | `medium`            | labels, buttons, table headers, nav items, badges |
  | 600    | `semibold`          | h2 to h4, card titles, key numbers                |
  | 700    | `bold` or `display` | h1 only                                           |

- `xs` (12px) is for timestamps and footnotes only, never uppercase.
- Numbers use `ui.num` (tabular) and are right-aligned in tables. Codes use `ui.mono`.
- Diacritics check: render "Quản lý đơn vị & nhóm · Bảo mật tài khoản · Điểm tuyệt đối · Ưu tiên"
  at the smallest size the screen uses. No mark clips or touches the line above.

## Colour

- `primary` (teal): the primary action, links, selection, focus. One primary button per view.
- `accent` (hoa mai yellow): achievements only (points, earned badges, the completed ring). Never
  navigation, tips, warnings or decoration. Text on a light surface uses `accent-ink`.
- Status tones mark state only. `danger`: error, destructive action, overdue, failed. `warning`:
  needs attention soon. `success`: done, passed, active. `info`: a neutral system notice.
- `*-subtle` fills are for alerts and selected rows or options, not for decorative tiles or covers.
- Charts take series colours from `ui.chart`. A series uses a status colour only when it means that
  status.
- A screen is neutrals and `primary`, plus status tones where there is state, plus `accent` where
  there is an achievement.

## Shape and elevation

- Radius by role: `ui.radius(sm)` for badges, tags, checkboxes and tooltips; `ui.radius(control)`
  for buttons and segmented controls; `ui.radius(field)` for inputs, selects and textareas;
  `ui.radius(card)` for cards, dialogs, drawers and popovers; `ui.radius(md)` for alerts, toasts and
  menus.
- `ui.radius(full)` only on avatars, switches, progress bars and status dots. Never `xl`, never a
  pill-shaped button, badge or chip, never a new radius value.
- Flat. A 1px `border` separates surfaces. Shadows only on what floats: popovers, menus, dialogs,
  drawers, toasts.
- No card inside a card, and no card around a single value.

## Layout and density

- Page header: the h1, an optional one-line description, and actions on the right with at most one
  primary. No eyebrow, no icon.
- Align left. Centre only a single focused form (sign-in) or a whole-page error (403, 404).
- Admin tables keep one line per row. Truncate long text with `ui.truncate` and a `title`, and put
  two facts in two columns rather than stacking them in one cell.
- A table row shows at most one inline action. The rest, and every destructive action, go in a row
  `ui-menu` or the detail view; clicking the row opens the detail.
- Status in a table is one `uiBadge` with `dot` per row, and no other coloured badge on that row.
- KPIs are a row of label (`text-muted`) over value (`ui.num`, `semibold`), with an optional delta.
  No card per number unless each one links somewhere.

## Motion

- Allowed: overlays opening and closing (dialog, drawer, popover, menu, toast) in `ui.duration(fast)`
  with at most 4px of movement; `reward-pop` at the moment an achievement is earned; `shimmer` on
  skeletons; `spin` on spinners.
- Not allowed: `ui.animate(enter)` on page content, cards, empty states or headers; hover lifts
  (`translateY` on hover); parallax; looping decoration.

## Copy

- Copy comes from the mockup, except the banned kinds above. Drop slogans, greetings, self-praise
  chips and mockup notes, or replace them with plain words, and list each as a deliberate difference.
- A title is a noun ("Người dùng") or the action being confirmed ("Khóa tài khoản Giảng viên Demo?").
- Helper text is what a colleague would tell you ("Dùng tài khoản nội bộ do Ban cấp"), not a
  description of the product.

## Themes

- Style a screen once, with semantic tokens. A component never branches on `data-palette`.
- A palette changes colours, fonts and textures through tokens. It must not bring back a banned
  pattern: Cobalt's gradient hero and `control: 999px`, and Giấy's dot-grid texture, are known
  violations.

## Known violations (do not copy)

The first port of the mockup left these in the code; `docs/reports/design-system-review.md` §5
schedules their removal. Do not copy them into new code and do not extend them. Fix one only when
the task is that fix, then delete its row here.

| Pattern                    | Where                                                                                                                                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Eyebrow                    | `ui.eyebrow` and the `eyebrow` token; the `ui-page-header` `eyebrow` input (passed by users, org, roles, profile); sign-in, change-password, course card, sidebar groups, theme controls, `/design-system` sections |
| Uppercase labels           | `_table.scss` (header cells), `_menu.scss` (group label), the course card meta                                                                                                                                      |
| Icon tiles                 | `ui-kpi` (its `icon` input is still required: pass one, but add no tile anywhere else), `.list__icon`, `.dialog__icon`, `.empty__art`, the `/design-system` principles grid                                         |
| Status tone as category    | `shared/status/role-badge.ts`, `shared/course/required-mark.ts`                                                                                                                                                     |
| Coloured edges             | `_toast.scss`, `_tip.scss`, `layout/sidebar/sidebar.scss` (`nav-indicator`)                                                                                                                                         |
| Gradient, watermark, glass | the `/design-system` hero, the sign-in brand panel watermark, `layout/header/header.scss` (`backdrop-filter`), the `hero-*` tokens, Cobalt's hero                                                                   |
| Placeholder art            | the `shared/course/course-card` cover and the `cover-*` tokens                                                                                                                                                      |
| Flat semibold              | `_badge.scss`, `_btn.scss`, the labels in `_field.scss`; the display font on h3 and h4 in `global/_base.scss`                                                                                                       |

| Copy                       | the sign-in slogan, "Chào mừng trở lại" and the always-on mockup note; the `/design-system` hero, its chips and the "Skill gợi ý cặp 'Financial Trust'" line                                                        |
| Chart colours              | `chart` 3 equals `warning`, 4 is Tailwind violet, 5 equals `danger`                                                                                                                                                 |

The `/design-system` page still demonstrates most of these. Until it is rewritten, use it to look up
a component's API, not its look.

## Checklist

Run it on every changed screen or component at 1280 and 375px, light and dark, and report it with
the angular.md §14 checklist.

1. No eyebrow, and no uppercase text except acronyms and codes.
2. No icon in a tinted tile or circle. Every icon is size `sm` or `md` and sits next to its text,
   or is an icon button with an `aria-label` and a tooltip.
3. Status tones only on state. Red only for an error, a destructive action, overdue or failed.
   Yellow only for an achievement.
4. At most one coloured badge per row or card. Attributes are text.
5. No gradient, watermark, glass, or coloured edge wider than 1px.
6. No hero or greeting. The first screenful shows real content.
7. Empty states: inline is one muted line and an action; a whole-page one is left-aligned.
8. At most three font weights. Display font only on h1 and h2. No `xl` radius; `full` only on
   avatars, switches, progress bars and dots.
9. No entrance motion on page content.
10. No slogan, greeting, self-praise or mockup note in the copy.
11. Squint test: blur the screenshot. The page title and the primary action stand out first.
12. Every difference from the mockup's look is listed in the pull request as deliberate.
